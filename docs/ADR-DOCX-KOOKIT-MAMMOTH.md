# ADR — Kookit DOCX conversion chain inside the native secure reader

Date: 2026-10-03. Status: implemented fixed-engine Mac slice; conversion/security/source/isolated native bridge tests and builds verified. This follows the user's agreed Kookit/WKWebView direction. It supersedes the narrower [native semantic candidate](ADR-DOCX-SEMANTIC.md), whose `fafd0a6` / `c9630ed` commits remain unchanged for comparison.

## Actual reused engine and provenance

The pinned [Kookit DocxRender](https://github.com/koodo-reader/kookit/blob/95f602ed62d204af0de9278cf53212c309b34bfc/src/renders/DocxRender.ts) calls `mammoth.convertToHtml({arrayBuffer})` and wraps the resulting HTML. Its original file is retained unchanged and Git-blob-checked in the vendor manifest. `engine-build/docx-adapter.js` actually invokes that original conversion chain, with a bounded input and explicit options/failure propagation. It uses the existing native reader/notes shell rather than importing Kookit's full GeneralRender/HTML-book application behavior. There is no hand-written replacement OOXML renderer or native semantic fallback on the product path.

Mammoth is fixed to **1.13.0**, within Kookit's declared `^1.8.0` range. [Official source metadata](https://github.com/mwilliamson/mammoth.js/blob/1.13.0/package.json) and its [BSD-2-Clause license](https://github.com/mwilliamson/mammoth.js/blob/1.13.0/LICENSE) were reviewed. `MAMMOTH-SOURCE-CHECKS.json` verifies four installed conversion/browser/license files byte-for-byte against the exact official GitHead and enforces their hashes during build. `MAMMOTH-SOURCE.json` records the official npm tarball SHA-512 integrity, gitHead, browser substitutions and dependency declarations. `package-lock.json` fixes all resolved packages to registry.npmjs.org; `npm ci` verifies integrity with lifecycle scripts disabled and a separate build cache/user config. No user document is sent to npm or a service.

`DOCX-DEPENDENCIES.json` inventories installed JS/build metadata and actual license files; duck's generic npm `BSD` declaration is recorded alongside its actual BSD-2-Clause text. `DOCX-BUNDLE-INPUTS.json` records **301 source inputs**, and `DOCX-BUNDLED-DEPENDENCIES.json` records **13 actual packages**: Mammoth 1.13.0, xmldom 0.8.15, base64-js 1.5.1, dingbat-to-unicode 1.0.2, JSZip 3.10.1, pako 1.0.11, lop 0.4.2, option 0.2.4, Underscore 1.13.8, xmlbuilder 10.1.1, immediate 3.0.6, lie 3.3.0 and setimmediate 1.0.5. BSD/MIT declarations and pako's original zlib notice are retained in full in the generated app `Resources/DOCX/Notices.txt`; JSZip selects its MIT alternative. Esbuild remains a build tool. PDFno modifications stay AGPL-3.0-or-later; no third-party relicensing claim is made.

The build chooses readable JSZip source rather than its prebuilt minified browser bundle, and explicitly excludes Node streams for this ArrayBuffer-only reader. Enforce Mammoth's `browser/unzip.js` and `browser/docx/files.js`, excluding Node fs/external-file code, Rangy, PDF, EPUB, extra engines and Chinese conversion from the DOCX bundle. Rebuilding EPUB after adding DOCX leaves its engine, notices and input manifest byte-identical.

Official npm audit reports an existing Rangy high prototype-pollution advisory outside this DOCX profile. [GitHub GHSA-65rp-mhqf-8gj3](https://github.com/advisories/GHSA-65rp-mhqf-8gj3) says patched versions **None**; npm's suggested upgrade is not patch evidence. No Rangy fix or EPUB security claim is made here. The coordinator has been notified; Rangy is absent from this DOCX bundle.

## Preflight, conversion and resource boundaries

Native ZIP validation remains: 20 MiB input, 1000 entries, 4 MiB per actual expanded entry, 50 MiB aggregate, expansion-ratio checks, CRC/actual length/consumed input, central/local agreement, descriptor checks, safe/case-normalised/Unicode paths, contiguous entry coverage, no symlinks/special files/encryption/ZIP64 or executable/macro/embedded-object paths. Memory-only decompression links system libz. Foundation XMLParser preflight checks every XML/relationship part, UTF-8 encoding, no DTD/entities/NUL, depth 64, 64 attributes and 100000 nodes per part. It checks ordinary Word document type/root relationships, unsafe constructs and bounded/cycle-checked styles. **Preflight does not generate product paragraphs or headings.**

Allow ordinary external hyperlink relationships to pass as inert metadata; never resolve/open their targets. Other external relationships, attached templates, macros, embedding/alternative HTML chunks and escaping/missing internal resources are refused. Mammoth receives the validated original bytes with `externalFileAccess:false`, `includeEmbeddedStyleMap:false`, default style maps, explicit empty-paragraph handling and an image converter that never reads image bytes. Images become escaped inert labels. No document-defined map, active content or external resources are rendered.

Mammoth's HTML is parsed in the fixed xmldom dependency with a strict namespace/tag allowlist, no DTD/entities and output node/depth/text budgets. Strip all source attributes, including every href/src/style/event/ID; preserve only bounded table spans. Drop active/unknown elements; hyperlinks retain label text. Add trusted paragraph IDs/offsets, flatten only necessary paragraph wrappers and emit canonical semantic blocks. Preserve Mammoth's standard h1–h6 headings, strong/emphasis, lists, simple table structure and inline semantics that survive the allowlist. The bounded generated HTML enters the view only after conversion succeeds.

The host is the same native WKWebView architecture: nonpersistent data store, default-deny CSP with nonce-authorised trusted scripts, protocol content rules blocking http/https/file/data/ftp/ws/wss, a custom scheme serving only the exact local engine.js path, no new windows or external navigation. Conversion happens in WebKit's content process with a 20-second readiness/conversion deadline and proper rejected-promise handling. Session/book/edition/hash/engine/extraction identity is checked at the native bridge; close/reopen changes the generation before preflight can suspend, rejects pending continuations and refuses a late opening request. Stale callbacks cannot resume another conversion.

## Canonical source and persistent notes

Canonical text comes from the **actual sanitised Mammoth output**, partitioned into trusted semantic paragraphs and joined with LF. It is not a Word page coordinate, original XML byte offset or legacy EPUB CFI. Generated list markers are outside canonical text. Native decoding validates contiguous IDs/UTF-16 offsets, table/list/heading ranges, at most 10000 blocks/100000 runs/1000000 UTF-16 units and bounded warnings. After insertion, compare actual DOM text against the native canonical DTO; mismatch fails closed.

Anchors bind original SHA-256, edition UUID, `docx-mammoth-utf16-1`, semantic block ID, exact scalar-preserving UTF-16 quote and prefix/suffix. Split surrogates, changed quote/context/version/edition fail; there is no fuzzy relocation. Reuse the existing selection snapshot, local note, highlight projection, outline jump and exact return workflow. The repository binds only the current trusted rendered document in memory, hashes the retained original before writes, and refuses note/progress writes until canonical binding exists. It does not reparse using the native candidate. Suppress stale/provisional progress writes while changing documents.

Use **`docx-mammoth-v1.json`**, with atomic commits, validated previous-manifest backup and `<sha256>.docx` originals. Keep any old candidate `docx-v1.json` untouched; there is no automatic offset migration. Reopening reparses with the actual pinned engine and revalidates notes against its output. Future engine/extraction changes need explicit source-version/migration review. DOCX AI and conversion are still outside this reader slice; old PDF/EPUB AI snapshots cannot act on active DOCX.

## Compatibility limits and integration

The persistent banner clearly states semantic reflow differs from Word page layout, fonts, headers/footers and pagination. Images/drawings and external resource access are excluded; style/field fidelity and all Word constructs are not guaranteed. The heading directory follows Mammoth-recognised h1–h6; custom/inherited/outline-only styles may remain paragraphs with conversion warnings. Word-generated UTF-8 Transitional DOCX within budgets is the first accepted profile; Strict OOXML, UTF-16 XML, ZIP64, encrypted/macro-enabled/embedded documents and old DOC are not advertised. Ordinary external hyperlinks now work as safe text. No claim of Word-identical layout or universal DOCX compatibility is made.

Existing shared-library routing from `c9630ed` remains. Integrators must reconcile `Package.swift` (Readers now depends on Services for unavoidable preflight and includes the DOCX resource), the existing DOCX import/sidebar/sample routes, active-format deactivation and AI guards. Keep the root chosen for local versus test storage unchanged. New JS build/source/license files and generated DOCX resources accompany the Swift module. No Xcode project regeneration is required. Preserve the old candidate commits and stores on rollback.

See [validation](DOCX-VALIDATION.md) for exact tests/commands. The offscreen WKWebView unit proves actual native conversion, canonical DOM, safe hyperlink text, selected quote and exact return without a visible/key/main window or launching the user's app. Manual visible-reader geometry, keyboard/accessibility, arbitrary Word corpus coverage, note editing/deletion, mobile DOCX UI and exported layout acceptance remain unverified; no desktop UI suite or user-app manipulation was performed.
