# ADR 0005 — Independent Mac DeepSeek short-sentence self-test

Date: 2026-10-03. Status: existing native entry implemented and diagnostics visibility repaired; model development requests use intercepted synthetic data only. Unauthenticated DNS/TLS/HTTP reachability is verified separately; actual authenticated generation, cost and language quality are **NOT-RUN**. The reader AI remains the offline slice in [ADR 0004](ADR-0004-SELECTION-AI.md).

## Authorised scope and user action

The requested provider is DeepSeek, base endpoint `https://api.deepseek.com`, model `deepseek-flash`. This entry is a separate Mac native sheet under model settings. It never reads the current book/selection/notes, provider preview secret, existing Keychain or another app. Opening settings, opening the sheet or importing/reading a book does not submit a request. There is no automatic test, fallback, retry or account setup.

The complete outbound messages are displayed before submission:

- System instruction: `Translate the following original test sentence into Simplified Chinese. Return only one short sentence.`
- User sentence: `A small blue bird rests beside a quiet window.`

Both are original PDFno text. Endpoint, path, model and text are immutable in this limited entry. The user must manually enter a new temporary key in this sheet's SecureField, explicitly confirm the displayed content and fee scope, and personally click the final send button. Keys are never taken from chat, screenshots, accessibility, logs or configuration preview. An agent must not fill/read/copy a real key or click live submission. A configuration-complete message does not establish consent to charges or actual connection success.

The proposed budget is at most RMB 1, with at most three submissions in this application session, 128 output tokens each and thinking disabled. Each send requires explicit user scope/budget confirmation. This client cannot enforce the provider's monetary bill cap or know an account's current billing price; its numeric limit is requests/tokens, not a guaranteed RMB stop. Provider-side fee limits do not authorise an agent to read or submit a key. Failed/cancelled/timed-out submissions conservatively consume an attempt and may still be charged. Reopening the sheet or clearing its records keeps the count; app restart resets this in-memory development counter, so it is not a durable account-level budget and must not be used to bypass the agreed request limit. Each send requires new manual input. No automatic retries.

## Native service and transient state

`DeepSeekSelfTest` is a bookless actor, not an `AIRequest` with fabricated PDF/EPUB anchors. It posts native JSON to the literal `https://api.deepseek.com/chat/completions`, with `Authorization: Bearer …`, `stream:false`, `max_tokens:128` and `thinking:{type:disabled}`. No files, images, tools, history, hidden reader context or retrieval chunks are included. It uses the shared ephemeral `URLSessionAITransport`: no cookie/cache storage, all authenticated redirects refused, and an actual 64 KiB response budget. No TLS/ATS exemption, server-side key relay or new SDK is introduced.

The actor validates consent/key before any submission and limits the total to three. A single continuation owner resolves worker/30-second-deadline/cancellation races; late responses cannot complete a cleared request. Native UI generation checks also prevent closed results from reappearing. Status errors are fixed messages for auth/quota/rate limit/redirect/network/server/format/cancel/timeout; raw error, response, headers, URL or key is never logged or copied to UI. A response must contain one assistant plain-text choice with `finish_reason:stop`, without tool/function calls, within 2,048 UTF-16 units. Truncated output is rejected rather than presented as a successful completed test. Rendering is `Text(verbatim:)`, with no HTML, link execution or tool handling.

Input clears when send begins; closing/cancelling clears input/confirmation and cancels unfinished work, but preserves safe response/error records in the same model until application exit. A pending record becomes explicitly cancelled; its late response cannot replace that outcome. Completed results and errors survive repeated close/reopen. Only an explicit, idle-state clear-records button removes them, without resetting attempts. The transient request needs an in-memory Authorization value until URLSession completes/cancels; Swift strings and framework buffers do not promise secure zeroisation. No credential, response, usage record or request is written to disk, Keychain, learning notes, iCloud or Bookno. Persistent Keychain activation and full reading BYOK remain separate future work. Existing application data schemas and originals are unchanged.

Records are shown before settings in a geometry-constrained, wrapping vertical ScrollView. Each outcome update scrolls to the latest record; an always-available toolbar button also navigates there. Each ordinal is labelled waiting/completed/safe failure, including HTTP 401/403, 402 and 429 categories; an output-limit `length` response has a distinct truncated failure rather than a generic success. A 30-second expiry stays visible. The count alone never implies success. The old close handler cleared responses/errors while retaining the count, causing the reported 3/3-cleared ambiguity; previously deleted outcomes cannot be recovered by this source fix. No attempt to read an old running instance's secrets or state is made.

## Existing open app, validation and handoff

When a user has already entered a temporary value in an open older build, source changes and isolated builds must not quit/restart it without explicit update permission, read its input region or overwrite its running bundle. Updated builds use a fresh derived directory for the same existing PDFnoMac target; no new app identity, target or test entrance is created. After permission, only normal quit and reopening the updated existing program are allowed; if an unsaved-document confirmation appears, stop for the user. Temporary input is not promised across restart and must be re-entered by the user. No final real submission is clicked by the agent. Local real-app UI tests that would relaunch the user's bundle are deferred to the separate CI machine. No screenshot or accessibility read of the entered key region is allowed.

Offline tests use only obviously synthetic keys, fixed synthetic response bodies and URLProtocol interception of **every** URL. They verify fixed host/path/model/messages/headers, consent before work, request/token limits, no retry on error, safe HTTP/JSON errors, redirect refusal, noncooperative cancellation/timeout, cleared native input and ignored late UI results. Ordinary PDF/EPUB/mock acceptance remains intact in CI. Exact counts, builds and exact-SHA CI evidence belong to [VALIDATION](VALIDATION.md).

Manual user acceptance: run the updated existing Mac product when ready; open model settings → its existing DeepSeek short-sentence self-test; read scope/limits and confirm the fees if accepted; enter a new key locally; personally click one request; inspect the latest top record (or toolbar “view test records”). Close clears the key but preserves outcomes for reopening. Do not reset/restart solely to bypass the three-attempt limit or copy keys into chat/logs. A real successful response and the provider's own billing are the only evidence of authenticated generation/cost; intercepted tests and compiling an entry do not establish either.

On 2026-10-03 at 08:23:45 UTC, a permitted local check with an empty environment and no proxy/credential file lookup resolved `api.deepseek.com`, validated its certificate/hostname and negotiated TLS 1.2, then received HTTP 401 from `GET /models` without Authorization, cookie or request body. The earlier sandboxed DNS check failed with `gaierror` code8; only after normal permission review did the read-only check run. No model generation or authenticated request occurred. This establishes that this machine reached the unauthenticated authentication boundary at that time, not that a key, balance, generation endpoint, JSON output or real account works.
