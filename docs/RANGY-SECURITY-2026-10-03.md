# Rangy dependency repair — 2026-10-03

The coordinator reviewed [GHSA-65rp-mhqf-8gj3 / CVE-2023-26102](https://github.com/advisories/GHSA-65rp-mhqf-8gj3) and the [upstream report](https://github.com/timdown/rangy/issues/478). The reviewed advisory lists affected npm versions <=1.3.1 and describes prototype pollution through recursive `util.extend`. Its patched-version field was still empty when read; this report does not claim that field names1.3.2.

The existing lock and generated EPUB resource actually contained **Rangy1.3.0**. Both `rangy-core.js` and `rangy-textrange.js` occur in `BUNDLE-INPUTS.json`; fixed Kookit GeneralRender/note/touch utilities import them. The vulnerable function therefore shipped in the trusted content runtime. Book scripts remain disabled in sandboxed frames, bridge/native inputs are constrained, and no route from an actual malicious book into the dangerous merge was demonstrated. Dependency inclusion is confirmed; successful exploitation, account/secret access or user-data damage is not established. No user book, running app, key, screenshot or live input was inspected.

The minimal change pins official **Rangy1.3.2**, preserving Kookit/PDFKit and all other dependency versions. Official npm metadata gives integrity `sha512-fS1C4MOyk8T+ZJZdLcgrukPWxkyDXa+Hd2Kj+Zg4wIK71yrWgmjzHubzPMY1G+WD9EgGxMp3fIL0zQ1ickmSWA==`. Only that package changed in the lock. Installation used the public official registry with empty npm configuration and all scripts disabled; no existing npm credential was read.
