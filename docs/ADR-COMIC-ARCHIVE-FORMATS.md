## Useful result and exact support

The native Mac import/library now accepts **CBT containing one uncompressed POSIX USTAR archive** and reuses the fixed Kookit `makeComicBook`, isolated comic WKWebView, native controls, deterministic page order, cover/landscape/portrait pairing, LTR/RTL, page jump, acknowledged progress and restart restoration. CBZ keeps its existing ZIP implementation. Original containers retain their real extensions and bytes; renaming ZIP to CBT or TAR to CBZ fails. CB7 and CBR remain explicitly unavailable and absent from the picker. Mobile compiles shared parser/model code but does not open either comic format.

| Container | Accepted local slice | Explicitly unsupported |
| --- | --- | --- |
| CBZ | Existing stored/DEFLATE ordinary ZIP, static PNG/JPEG | Existing ZIP encryption/split/ZIP64/other compression rejection remains |
| CBT | Exact `ustar` + NUL / `00` headers; ordinary file type `0` or NUL and directory type `5`; UTF-8 name/prefix; octal numbers; unsigned header checksum; zero alignment padding; two zero end records and optional additional zero records | V7/GNU TAR, PAX headers/global headers, base-256 numbers, sparse/longname extensions, links/devices/FIFO/other types, nonzero link targets/device numbers, directory payloads, concatenated/nonzero trailing archives, gzip/bzip2/xz wrappers, incomplete records, external encrypted/multi-volume wrappers |
| CB7 | None | Every 7z codec/structure, including stored COPY, LZMA/LZMA2, solid, encoded/encrypted headers and multi-volume |
| CBR | None | Every RAR version/compression, encryption and multi-volume |

CBT validates all records before rendering, including ignored ComicInfo/macOS/hidden metadata. Header checksums do **not** authenticate TAR payloads: USTAR has no per-file CRC. Stored original SHA-256 and exact admitted page manifest are revalidated on reopen. Names never become HTML/JS or disk paths for extraction. All regular pages must be ImageIO-complete single PNG/JPEG and use the existing bounded static image admission/downsampling; recognized unsupported image formats fail instead of silently dropping pages. ComicInfo does not change order/direction. Only the current one/two downsampled pages reach the same trusted Kookit profile; no new content runtime or JS resource is added.

Limits are inherited: 100 MiB input (bounded file read), 2000 records including metadata/directories, 16 MiB per payload, 512 MiB declared total payload, 24M pixels/image, 512M pixels/archive, 16000 per dimension, max 2400 thumbnail dimension. Because accepted TAR is uncompressed and input is capped at 100 MiB, its effective aggregate payload ceiling is below 100 MiB. Parsing checks cancellation at records/images, scans bounded input without a second archive-sized byte array, and retains payload ranges. No filesystem extraction, shell archiver, external content execution, network/content resolution or overwrite of existing original is performed.

## Storage, compatibility and rollback

CBZ continues to use `comics-v1.json` and `Originals/<sha256>.cbz`; CBT uses `comics-cbt-v1.json` and `Originals/<sha256>.cbt`. The actor combines validated books for display but writes only the selected format manifest. `ComicBook` keeps the existing Codable fields; format is derived from the validated original extension and checked against the particular manifest. Legacy CBZ manifest bytes/schema are not migrated or rewritten by CBT import/progress. Each changed manifest receives its own validated atomic backup. Both stores reject future/corrupt/unknown-field manifests; a corrupt constituent stops combined library/import writes instead of discarding it. Existing hash-named originals are compared and never overwritten; an equal orphan can be reused, while a collision is refused.

A downgrade can still open old CBZ books without seeing CBT entries. Cover metadata adds explicit `.cbt` and `.cbtFirstImage` tags; an older app refuses `covers-v1.json` containing those tags rather than accepting a wrong CBZ source. The prior cover manifest backup permits manual rollback; old/current cover assets remain retained by the existing cover service. User-selected CBT covers follow the existing cover revision/restore behavior. No private library or persisted user data was accessed for testing.

Cross-process transactions remain unimplemented. Interruptions may leave an unreferenced new original, as in the old comic route; no corrupt/future manifest is repaired automatically. Source identity and progress include exact edition/hash/page/index/direction/layout; a source change refuses restore. Comic OCR, AI, notes/region anchors, zoom/original-resolution viewing, continuous scroll, broad accessibility and device UI remain outside this slice.
