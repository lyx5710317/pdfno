# TXT / Markdown / HTML Mac first reading slice

Date: 2026-10-04. Base: `11d32265a8b7ee7956f36c6af59dd42e54dcf035`. Branch: `feature/text-formats`. Status: implementation and isolated runtime unit tests passed; full native UI acceptance pending. This slice does not change the independent project's UNVERIFIED / platform-blocked security-audit status.

## Delivered scope

Mac native file import and library rows route `.txt`, `.md` / `.markdown`, `.html` / `.htm` (case-insensitive) to an independent reader. The native workspace supplies title/chapter navigation, selected quotation capture, local notes, validated source return and persisted reading progress. It uses the existing native shell rather than opening a browser application. TXT headings are Kookit heuristic chapter titles; Markdown and HTML expose all h1–h6 levels. Unchaptered text remains readable without synthetic chapter text entering quotations.

XML, XHTML, MHTML, heuristic encoding detection, search, note editing/deletion, custom covers, AI text-format requests and mobile text reading remain outside this slice. The long-term eighteen-format requirement is unchanged. HTML/HTM are adapter aliases, not evidence for XHTML/XML/MHTML coverage.

## Content, encoding and memory budgets

`TextFileDecoder` accepts strict UTF-8 (optional UTF-8 BOM) and UTF-16LE/BE with BOM. It validates UTF-16 surrogate pairing and does not silently substitute replacement characters or guess Shift-JIS/GB encodings. Unsupported encodings have an actionable Chinese error directing the user to save a supported encoding. HTML charset declarations must agree with the detected encoding; ordinary HTML doctype is allowed, XML declarations and DTD/entity declarations are refused. Binary control characters, empty input and UTF-32 BOMs are refused.

Limits are 4 MiB original bytes, one million decoded/canonical UTF-16 units, 10,000 TXT lines/semantic blocks, 100,000 markup delimiters before parsing / traversed DOM nodes / runs, 64 source nesting levels, 4 Mi UTF-16 intermediate HTML, 10 MiB bridge JSON and 20 seconds for engine conversion/readiness. Imports use the existing regular-file bounded reader. JS bounds traversed work and buffered paragraph text, and only one rendered canonical document is cached. These are input/structure/working-data budgets, not a promise of a fixed operating-system RSS quota; WebKit parsing/Marked/native strings still have transient copies. Very large files and complete document fidelity remain out of profile.

An inert DOM parser reads book markup under the already installed CSP/content rules. Active branches are removed, ordinary links become text, image alt labels remain text, CSS/fonts/resources are not read, table text follows reading order, and ruby rt/rp are omitted with a visible warning. Only semantic text, heading/emphasis metadata and fixed warnings cross the checked session/book/edition/hash/version bridge. Swift regenerates escaped paragraphs through the existing trusted DOCX HTML/selection/progress bridge; raw HTML, source attributes, IDs, URLs, styles and scripts are never installed in the live reading DOM. No raw-source error or source text is printed.

The WebKit store is nonpersistent. Per-protocol resource rules, default-src/connect-src/img-src/frame-src/object-src denial, the single `pdfno-text://app/engine.js` native asset allowlist and initial-about:blank-only navigation policy are retained. Clicking displayed ordinary link text has no navigation action. There is no automatically opened link and no external-open command in this slice. Opening/switching formats cancels existing selection/page AI tasks and excludes hidden PDF/EPUB sources while the text reader is active.

## Exact quotation definition and storage

Original bytes, including Markdown syntax and line endings, are retained unchanged and addressed by SHA-256. `text-formats-v1.json` and `.backup` are independent of existing PDF/EPUB/DOCX/comics/learning manifests. The asset is `Originals/<sha256>.<txt|markdown|html>`; original filename and actual format remain in the record. Deduplication is by original hash plus format, allowing the same bytes to have distinct TXT and Markdown meanings; HTML/HTM aliases deduplicate together.

An anchor binds edition, original-file SHA-256, extraction version `kookit-text-marked15-utf16-1`, block ID, checked UTF-16 start/end, exact quotation and up to 64 UTF-16 context units. Its offsets refer to **the displayed canonical semantic text**, joined between blocks by LF. TXT CRLF/CR becomes LF; Markdown syntax is converted by fixed Marked; HTML entity/line-ending semantics come from inert HTML parsing. Ruby readings and unsupported content are excluded. These are neither raw file byte offsets nor original Markdown source spans. No approximate/fuzzy relocation or fabricated original source offset is offered.

The trusted rendered DTO and actual live DOM text must agree exactly before reading becomes ready. Saving notes/progress requires bound canonical output and exact scalar/surrogate validation. Reopening verifies original identity and reruns the same engine/version before restoring anchors. A mismatch preserves the stored note and refuses an inexact return. Corrupt/future/unknown-field manifests stop writes; previous validated manifest is backed up before atomic commit. This is additive storage with no real-user migration or automatic downgrade/deletion.
