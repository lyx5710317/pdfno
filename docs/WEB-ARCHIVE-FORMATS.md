## Exact supported inputs

Extensions are `.xhtml`, `.mhtml`, `.xml`, case-insensitive; `.mht` is deliberately outside the eighteen-extension target. All are Mac-only at present. Source decoding remains strict UTF-8 (optional BOM) or BOM UTF-16LE/BE with valid surrogate pairs. XML encoding declarations, XHTML meta charset declarations and MIME charsets must agree with actual bytes. Unsupported encodings fail without replacement characters, heuristic guessing or a fallback parser.

XHTML must be well-formed XML with root `html` and namespace `http://www.w3.org/1999/xhtml`, including prefixed XHTML. One direct `body` is required; at most one direct `head` is permitted. The head is omitted. The familiar semantic HTML vocabulary in `ReadableXML.swift` is accepted; active branches are omitted. Images become escaped alt labels. Attributes, CSS, IDs, URLs and events do not enter the reading DOM. Foreign namespaces (including inline SVG/MathML), unknown elements, DTDs, entity declarations and processing instructions such as external stylesheets are refused. Predefined XML entities, numeric references and CDATA become ordinary escaped text. Even a standard external XHTML doctype is outside this finite profile.

Readable `.xml` accepts the same real XHTML document or an **unnamespaced `document` root** with the explicit vocabulary: `section`, `title`, `p`/`para`, `h1`–`h6`, `strong`/`b`/`bold`, `em`/`i`/`italic`, `br`, `list`/`item`, `ul`/`ol`/`li`, `blockquote`, `pre`, `code`, `span`, `a`, simple `table`/`tr`/`td`/`th`, `ruby`/`rt`/`rp`. `title` must be a direct child of document or section; it becomes h1 or a heading reflecting section depth, capped at h6. This is PDFno's documented small readable input profile, **not a claim to support DocBook, TEI, invoices, arbitrary business XML or automatic schema meaning**. Unknown roots/elements/namespaces fail. Documents without headings retain reading/notes/progress and an honest empty directory.

MHTML follows a deliberately finite subset of [RFC2557](https://www.rfc-editor.org/rfc/rfc2557.html) and [MIME transfer encoding rules](https://www.rfc-editor.org/rfc/rfc2045.html):

- Requires MIME-Version1.0 and one **flat multipart/related** entity with a 1–70 ASCII-character boundary; optional type must be text/html. Start uses an exact bracketed Content-ID; absent start chooses the first part. Exactly one HTML part is permitted, even if another alternative looks readable.
- MIME headers are ASCII, folded continuation lines are accepted, and names/parameters cannot repeat. Maximum128 fields,998 bytes per physical line and64KiB header section. Quoted parameter escaping/comments/RFC2231 continuations, nested multipart/alternative, messages, signed/encrypted/compressed entities, Content-Encoding and attachments are refused. Preamble/epilogue must be empty or whitespace. CRLF and LF archives are accepted; displayed hard line endings normalize to LF.
- Transfers are7bit/8bit, canonical padded base64, or strict quoted-printable (hex bytes/soft line breaks). Malformed transfer data fails. Text charset supports UTF-8, us-ascii (including ASCII default when omitted), or BOM-backed UTF-16/LE/BE. HTML meta accepts UTF-8 or the detected UTF-16; legacy charset declarations remain refused. A missing charset does not authorize non-ASCII text. Root bytes must satisfy both the MIME declaration and HTML decoding.
- Content-ID and normalized Content-Location identities are unique. Location may be HTTP(S) or relative to the root's HTTP(S) location; credentials, file/data/script schemes and ambiguous duplicates are refused. These are metadata identities only, **never a baseURL, fetch permission, cache request or external-open command**. Resource references are removed by the existing HTML sanitizer rather than resolved into loaded resources.
- Additional parts may be text/css or signature-matching opaque PNG/JPEG bytes, within decoded limits; their bytes are validated for transfer/identity and discarded from rendering. Images are not decoded to pixels, and their validity/fidelity is not promised. SVG, animations, fonts, JavaScript, unknown binary/media types and extra HTML documents are refused even if the root could otherwise render. No original page, stylesheet, embedded asset or live URL is loaded; hyperlinks retain only text. The user sees these limits in the document warnings.

Limits retain 4MiB original, one million decoded/canonical UTF-16 units,10000 semantic blocks,100000 XML/DOM nodes/runs and64 nesting levels. MHTML adds64 parts,1MiB actual decoded bytes per part,4MiB total decoded bytes. XML projection has a4Mi UTF-16 intermediate HTML ceiling; the existing checked conversion bridge retains its10MiB JSON/20-second limits. Parsing/transient strings have bounded copies; this is not a fixed OS RSS guarantee. Cancellation, malformed inputs and over-limit archives are ordinary failures, with no retry/network recovery.

## Originals and source coordinates

The original complete XHTML/XML/MHTML bytes, original filename and format are retained in the existing independent text store. Assets are `Originals/<sha256>.<xhtml|xml|mhtml>`; manifests/backups remain `text-formats-v1.json`. Deduplication is hash+format, so identical XHTML bytes imported as XML have distinct book/edition meaning. No PDF/EPUB/DOCX/comic/learning schema is changed and no real-user migration is performed.

Only preflighted/projected HTML is passed to the existing fixed Kookit HTML conversion. Its output then crosses the session/book/edition/hash/version checks; Swift installs escaped semantic blocks and verifies live DOM text equals the DTO exactly. Raw source markup/MIME headers/resources never become live HTML. Existing custom engine URL allowlist, CSP, blocked protocols, navigation refusal, nonpersistent store, source return and stale-session protections remain.

Anchors still bind edition/original SHA-256/`kookit-text-marked15-utf16-1`/semantic block/exact UTF-16 span/scalar-exact quote/context. Offsets refer to **displayed canonical semantic text**, not XML source/byte spans, MIME part byte offsets, archive URLs, original page geometry or fabricated XML semantics. XML entities/CDATA/line endings and HTML sanitization can transform spelling. Reopen verifies the original and reproduces the same canonical route; changed text/version refuses exact source return and preserves the saved note. Old app versions with only the prior enum cannot read these added format values and protectively refuse the shared text manifest; preserve manifest/backup/Originals before downgrade. No automatic rollback/migration/fuzzy relocation is added.
