# Proposed ADR — Native DOCX semantic candidate versus Kookit/Mammoth

Historical candidate at `fafd0a6` / `c9630ed`, retained for comparison. The active route is now [Kookit/Mammoth](ADR-DOCX-KOOKIT-MAMMOTH.md); this candidate is not used for product semantics.

Date: 2026-10-03. Status: **pending architecture/user review; independent candidate only**. The candidate is implemented and its unit/security tests/independent builds are verified; interactive WebKit acceptance is deferred at the user's request. This does not replace the agreed Kookit DOCX direction or authorise merging a route change. Base: `aaba190a878df9de5674491d20f1b36fa4733607`.

## Proposed decision and upstream evidence

The agreed direction retains Swift/SwiftUI and PDFKit for PDF, with Kookit/WKWebView for other formats. **This branch differs in its DOCX engine**: Swift parses a restricted OOXML profile and WKWebView displays generated semantics; Kookit/Mammoth does not run for DOCX. This is a reviewable candidate, not a silently selected substitute. The integrator must assess whether this is a material architecture change and obtain the user's route decision before merging if required by their established approval preference. The existing Kookit resource is EPUB-only: its vendored manifest and bundle inputs exclude DOCX and Mammoth. The pinned public Kookit 1.0.4 [DocxRender](https://github.com/koodo-reader/kookit/blob/95f602ed62d204af0de9278cf53212c309b34bfc/src/renders/DocxRender.ts) calls Mammoth's HTML conversion and passes that HTML into its HTML-book wrapper. Its [package metadata](https://github.com/koodo-reader/kookit/blob/95f602ed62d204af0de9278cf53212c309b34bfc/package.json) declares AGPL-3.0-or-later and a **range** `mammoth: ^1.8.0`, not a resolved dependency tree. The public [license text](https://github.com/koodo-reader/kookit/blob/95f602ed62d204af0de9278cf53212c309b34bfc/LICENSE) is AGPL v3. This is evidence of the upstream adapter, not evidence that the application already ships DOCX or that any extra/proprietary engine is licensed.

[Mammoth 1.8.0's license](https://github.com/mwilliamson/mammoth.js/blob/1.8.0/LICENSE) is BSD-2-Clause; its [security guidance](https://github.com/mwilliamson/mammoth.js#security) describes unsanitised source conversion, possible JavaScript links and pathological performance. A future Mammoth adapter needs a pinned transitive-source/license inventory and independent sanitisation/resource limits. The reason for exploring this candidate is that the existing EPUB-only bundle has no resolved Mammoth tree, while the upstream path passes unsanitised generated HTML through; bounding and sanitising that engine requires a separate audited adapter. This does **not** establish that Mammoth cannot be safely integrated. This slice neither installs nor vendors Mammoth or the upstream DOCX adapter. It implements an original, deliberately narrower OOXML semantic parser and uses WKWebView only for escaped, PDFno-authored HTML. No claim of Kookit DOCX runtime integration or Word-equivalent layout is made.

`PDFnoDOCXZIP` is a small original C wrapper linking the Apple SDK/system `libz`; raw DEFLATE consumption, actual output size and CRC are checked. There is no external Swift package, copied zlib implementation, downloaded binary or additional JS dependency. PDFno-authored source and synthetic fixtures remain AGPL-3.0-or-later. System framework/library distribution terms remain separate.

## Product scope

Mac import, a separate DOCX library list, a bundled original example, reflowed paragraphs, direct bold/italic, tabs/line breaks, heading outline (explicit outline levels, named heading styles and bounded style inheritance), list nesting and simple table grids are wired into the native shell. Heading jumps and selected-text notes return to exact source offsets; progress and notes persist independently in `docx-v1.json`, with immutable `<sha256>.docx` originals and previous-manifest backup.

The persistent banner explains that this is **semantic reflow reading**, with different pagination/fonts/page layout from Word. Numbering is displayed as nested bullet items; table merge/size fidelity, images/drawings, headers/footers, footnotes/endnotes, original comments, complex fields and extensions are omitted with document warnings. Deleted tracked text is omitted; inserted text is read. OOXML Strict, non-UTF-8 XML, ZIP64, encryption/DRM, macro-enabled Word, embedded objects and DOC are outside the accepted profile. Any external package relationship is rejected, including ordinary external hyperlinks; the error directs users to save a plain local DOCX. DOC is explicitly rejected rather than sent to PDFKit or advertised as supported.

The existing notes workflow is reused: capture an immutable selection, show the quote, save local text/highlight and return to the original. DOCX has its own anchor/note types, avoiding reinterpretation of PDF coordinates or EPUB spine/CFI data. DOCX selection AI is not exposed; active DOCX rejects old PDF/EPUB AI snapshots. Conversion is a separate task, not implemented here.

## Security and source anchors

ZIP32 budgets are 20 MiB input, 1000 entries, 4 MiB per expanded entry and 50 MiB aggregate; suspicious expansion ratios are also refused. Check central and local names/methods/flags, descriptors, CRC, exact consumed compressed bytes, actual output length, complete contiguous local-entry coverage, safe paths, Unicode/case collisions, symlinks/special files, encryption, ZIP64 extras and forbidden executable/macro/object paths. Read memory only; never extract document paths to disk. File reads are bounded before decoding.

Parse every XML/relationship entry with Foundation XMLParser, namespace checks and external entities disabled. Reject DTD/entity declarations and non-UTF-8/NUL documents before parsing; cap nesting at 64, attributes per element at 64 and nodes per XML part at 100000. Validate the package office-document relationship and exact ordinary Word document content type. Reject external relationships, escaping internal targets, missing targets, templates/embedded packages/objects and alternative HTML chunks. Styles have a 32-step cycle-checked inheritance limit; output is capped at 10000 paragraphs and 1000000 UTF-16 units.

Original XML, HTML, URLs, CSS and scripts never enter WebKit. Generate only escaped text and fixed tags/styles. The page uses default-deny CSP, one random nonce for its trusted bridge, no network/image/font/frame/object resources, nonpersistent storage and native navigation denial after the initial local HTML load. The bridge checks main-frame/webview/session identity, native offsets and exact native quotes. Closing/reopening changes the session token; stale navigation callbacks cannot close another webview. There is a ten-second page-readiness timeout.

Canonical source is each paragraph's exact text joined by one LF, including table-cell paragraphs, excluding generated bullets/HTML. Anchors bind edition UUID, original SHA-256, extraction version, paragraph ID, global UTF-16 start/end, scalar-exact quote and up to 64 UTF-16 units of context on each side. Split surrogate pairs, changed quotes/context/versions and different editions fail; repeated quotes remain distinct. Repository writes reparse/hash the retained source and verify the exact anchor. Opening a notes sheet freezes the selection. Highlight projection uses ranges/CSS Highlights without modifying source text or originals. If CSS Highlights is unavailable, a native banner explicitly reports that saved highlight projection is unavailable while notes/exact return remain usable. There is no fuzzy relocation.

## Conditional integration and rollback

Only after the route review/required user confirmation may the integrator adopt this candidate. Alternatively, retain its original fixtures, security budgets, exact anchor contracts and native UI as reference while implementing an audited Kookit/Mammoth adapter; do not claim this branch fulfills that engine requirement. New module files are independent `DOCX*` source files and the `PDFnoDOCXZIP` target. Shared changes are confined to `Package.swift`, `LibraryModel.swift`, `LibraryWorkspace.swift`, and two source/third-party notice appendices. When integrating comics/conversion or AI work, manually reconcile these shared entry points:

1. Preserve the C target's `.linkedLibrary("z")`, add it to services dependencies, and retain the original DOCX UI resource.
2. Initialise `DOCXLibraryModel` with the **same already-selected local/test root** as other repositories. Include its manifest load. Route `.docx` before PDF, explicitly refuse `.doc`, and keep unknown-format rejection.
3. Add DOCX list/sample/import UTI and route the active DOCX workspace. On PDF/EPUB/comic switches deactivate DOCX; on DOCX success close any other WebKit format session. Preserve the existing PDF/EPUB AI cancellation and guard DOCX as unsupported for that AI source enum.
4. Keep native `DOCXAnchor`/`DOCXNote` separate. Do not migrate existing PDF/EPUB stores or reuse incompatible offset formats. When adding other formats, apply the same active-reader guard to AI.

No Xcode project regeneration is needed: the local Swift package automatically discovers sources. Rollback removes the routing/target/resource/new source files; leave existing `docx-v1.json`, backups and originals in place for a future compatible reader. Do not delete user assets or restore backups automatically.

## Compatibility risks, validation and remaining acceptance

The native subset can reject Word-authored documents with commonplace external hyperlinks/templates, ZIP64, different XML encodings or Strict namespaces; it can omit legitimate nested tables, images, advanced revisions, character-style inheritance and fields. Mammoth may cover more semantic constructs, so this candidate cannot inherit Kookit/Mammoth compatibility claims. Visible omissions are reported, but this is not a complete schema validator or full Word rendering engine.

See [DOCX-VALIDATION.md](DOCX-VALIDATION.md) for exact commands/evidence. Development uses only original fixtures and unique temporary stores. Desktop UI tests, the pre-existing window-creating EPUBWebKit suite, the user's application, real credentials, shared Library, push/merge and user documents are untouched.

Before declaring interactive acceptance, the coordinator should use a separately authorised isolated app/store to check first-page readiness, selection across styled paragraphs/table cells, outline scrolling, highlight projection, progress restoration, close/reopen and manual accessibility. The current JavaScriptCore test compiles/initialises the trusted bridge and checks canonical text, but does not prove DOM behavior or WebKit navigation. Cross-platform builds do not enable mobile DOCX UI. Image/font/layout fidelity, complete OOXML coverage, note editing/deletion, damaged-store recovery and conversion remain future work.
