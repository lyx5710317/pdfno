# Reproducible Kookit EPUB profile

This is build-time tooling, not an Electron/Node app runtime. PDF stays in PDFKit.

```sh
npm ci --prefix engine-build --ignore-scripts --no-audit --no-fund --registry=https://registry.npmjs.org
node --test engine-build/loader.test.mjs
node engine-build/build.mjs
```

Use Node 22+ and the committed lock. The build verifies original Kookit Git blobs, applies the checked script-disable transform, substitutes disabled PDF/Chinese modules and produces the EPUB-only engine plus full notices. Original `EpubRender.ts` is retained as the adaptation reference; the app uses `kookit-adapter.js` with a bounded loader and explicit async failures. `vendor/manifest.json` pins original source; `BUNDLE-INPUTS.json` identifies actual inputs. No upstream PDF engine, OpenCC mapping, extra product, fonts, test minified file or WASM is bundled.

The combined lock has 53 entries including the root and esbuild's optional platform packages. The EPUB-specific `DEPENDENCIES.json` records16 actual JS/build packages; the combined `DOCX-DEPENDENCIES.json` inventories26 installed package records and their original licenses/integrity. The installed platform esbuild package uses the upstream MIT license; it is a build tool, excluded from app resources/source distribution. JSZip selects MIT, pako retains MIT and its original zlib header, Rangy retains its actual npm 1.3.2 MIT file, and isarray's complete MIT text is preserved from its packaged README. Kookit core, CFI reference and embedded foliate licenses are preserved separately. See ADR 0003 and the dated source audit for upstream provenance limitations.

Generated app assets are committed for Xcode users; CI rebuilds and compares them. `node_modules` and compiler binaries are ignored. EPUB originals are local-only. Reproduction uses original fixtures generated by `scripts/generate-epub-fixture.py`; do not copy user books or unlicensed resources into tests.

## Fixed Kookit DOCX / Mammoth profile

`docx-adapter.js` directly invokes the same Mammoth conversion engine/API referenced by the retained Kookit DOCX class; it does not execute that full upstream class with fixed Mammoth 1.13.0. Native ZIP/XML preflight is mandatory before the trusted browser bridge, ordinary hyperlinks degrade to text, images are not read, and every converted URL/event/style is removed. The native candidate is not a fallback. Original `DocxRender.ts`, npm source metadata, actual license texts and separate DOCX dependency/input manifests record provenance. Readable JSZip inputs and the browser-only/no-Node-stream profile are enforced by the build; EPUB assets remain byte-identical.

```sh
npm ci --prefix engine-build --ignore-scripts --no-audit --no-fund --registry=https://registry.npmjs.org --userconfig=/dev/null
python3 scripts/generate-docx-fixture.py
node engine-build/generate-docx-extraction.mjs
node engine-build/build-docx.mjs
node --test engine-build/docx.test.mjs engine-build/loader.test.mjs
```

Mammoth source and the browser substitutions are verified against the committed official metadata/lock. Lifecycle scripts are disabled. `DOCX-DEPENDENCIES.json` includes actual license text information (duck's generic BSD metadata is BSD-2-Clause in its file); only `DOCX-BUNDLED-DEPENDENCIES.json` packages enter the resource, with full notices and pako's original zlib header. The old EPUB Rangy finding is recorded with its separate verified official1.3.2 source repair; GitHub's advisory still lists patched versions None. See `docs/RANGY-SECURITY-2026-10-03.md`; source/regression evidence, not metadata alone, supports that repair. DOCX excludes Rangy entirely. See the DOCX ADR for accepted source budgets and remaining compatibility/visible UI acceptance.
